## P0.5 — ОТМЕНА: МЯГКИЙ ПО УМОЛЧАНИЮ (решение 27.10, код — след. шаг)
**ФАКТЫ (прочитано по коду):** «мягкий/жёсткий» = ровно `foreground` vs `background`. `launchBackground(..., parentJob: Job? = null)` → `CoroutineScope(Dispatchers.IO + (parentJob ?: Job()))` ⇒ **`parentJob = null` ⇒ scope независим ⇒ ребёнок переживает отмену родителя**; `foreground` (`:878`, `:400`) исполняется в scope вызывающего ⇒ **отмена родителя гасит ребёнка ⇒ токены сгорают**. `spawnCustom` (`:394-396`) уже умеет считать роль спавнера: `app.chatRepository.dao.agentWorkerRole(spawnerSessionId)`.
**Решение:** дети, нанятые агентом (`spawnerRole != null`), запускать **detached** (фоновая машина, `parentJob = null`) ⇒ отмена родителя их не гасит; результат приходит через `onBackgroundResult` ⇒ доска (RUNNING→терминал, `CancellationException` перебрасывается — `:232-272`).
**ОБЯЗАТЕЛЬНОЕ УСЛОВИЕ (пазл):** API «дождаться/забрать результат по spawn id» сегодня НЕТ (регулярка `awaitResult|resultOf|childResult|results[` ничего не нашла)**сначала пазл, иначе родитель останется без результата ребёнка**.
**Факты:** `SubagentExecutor.kt:215` `launchBackground` — фоновые дети в своём scope ⇒ выживают отмену родителя (токены целы, результат на доске) ⇒ это уже «мягкий» вариант. `:778` `cancelBackground(spawnId)` — гасит фонового ребёнка. `SubagentTools.kt:33` — тул умеет только фоновых. **Foreground-дети умирают со scope хода ⇒ токены сгорают** ⇒ «жёсткий» достался mini-агентам по умолчанию.
**Решение:** дети ORCHESTRATOR ⇒ detached (свой scope + spawn id) ⇒ отмена родителя их не гасит; `cancel_subagent` получает параметр `scope=collect` (по умолчанию, не гасить) / `all` (гасить)**мягкий = основной**.
**Осталось:** (1) найти путь сбора результатов детей (регулярка `awaitResult|resultOf|childResult|results[` НЕ нашла ⇒ имя иное) и собрать пазл; (2) изоляция каталогов ребёнка («один файл — один ребёнок»); (3) учёт «осиротевших» детей на доске.
