# Plan-First Coding

Для любой задачи сложнее однострочника — план ДО кода. Экономит часы переделок.

## Цикл
1. **Разведка** (разведка, не догадки): найти реальные файлы/функции, которые тронешь. grep по именам, file_read существующего кода ДО правок.
2. **План**: 3–7 шагов, каждый с файлом и ожидаемым эффектом. Явно выписать инварианты («что не должно сломаться»).
3. **Правки**: минимальный дифф на шаг. Один шаг = одна логическая правка, не десять.
4. **Проверка**: собрать/запустить/погрепать результат. «Скомпилировалось» ≠ «работает» — доказать поведение.

## Правила
- Не начинай правки, пока не видел реального содержимого файла. Правка по памяти = правка по галлюцинации.
- Нашёл в разведке противоречие плану — план пересматривается, а не код подгоняется.
- Дублирование: прежде чем добавить функцию — поискать существующую. Нашёл — расширить, не копировать.
- Слабое место в собственной правке, замеченное сразу, — исправляется сразу, не «потом».

## Результат для юзера
План (кратко) → что сделано → что проверено и КАК → что осталось.
