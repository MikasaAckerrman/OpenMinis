# minis-uicopy — копирование интерфейса по скриншоту

Полная инструкция инструмента. Файл вшит в APK
(`assets/default_mount/usr/local/share/minis-uicopy/GUIDE.md`) и разворачивается
в rootfs при каждом запуске приложения, поэтому переживает очистку памяти,
сброс rootfs и переустановку скилов.

Читать так: `file_read /usr/local/share/minis-uicopy/GUIDE.md`

---

## Что это

Механизм пиксельной реконструкции UI по одному скриншоту. Не «похожий
интерфейс», а копия с измеренной ошибкой.

Доказано на реальном экране (CS 1.6 VGUI2, 1097×654, 13 итераций):
MAE 4.38 → 1.96, точных пикселей 89.5% → 95.0%, при этом
**RECONSTRUCTION-ошибка 0.41 MAE на 96% кадра** — остаток сидит в форме
глифов недоступного шрифта.

## Два принципа

**Ни одного значения «на глаз».** Каждый цвет, отступ, размер и профиль
границы берётся измерением из оригинала. Не измеряется — помечается как
неизвестное, а не выдумывается.

**Генератор не судит сам себя.** Вердикт даёт `diff` (числа), а не
впечатление «похоже». Каждая итерация обязана улучшить метрику.

## Обязательный цикл

```
ORIGINAL → measure → build → render → measured diff → diagnose → fix → render → …
```

Работать автономно. Вопрос пользователю — только при настоящем блокере
(информация физически недоступна из материалов).

## Команды

```sh
minis-uicopy init <screenshot>     # подготовить папку (копия как ORIGINAL.png)
minis-uicopy doctor                # проверить окружение

# ИЗМЕРЕНИЕ (0 токенов)
minis-uicopy measure hist          # палитра: цвета и % площади
minis-uicopy measure frame         # границы кадра/диалога
minis-uicopy boxes                 # связные компоненты = элементы с боксами
minis-uicopy probe                 # bevel-профили, цвета текста, ink-высоты

# CSS ИЗ ИЗМЕРЕНИЙ
minis-uicopy stripes               # разделители, кромки, footer-separator
minis-uicopy bevel                 # ПОЭЛЕМЕНТНЫЕ профили кнопок и полей
minis-uicopy edges [шаг]           # внешние кромки как измеренные градиенты

# ШРИФТ (по растру, не на глаз)
minis-uicopy fontfit               # family × size по ink-ширине (PIL, быстро)
minis-uicopy textfit               # прямое растровое MAE через chromium
minis-uicopy spacefit              # ПОСТРОЧНЫЙ letter-spacing

# ЦИКЛ
minis-uicopy render <html> <out>   # рендер + обход дефекта обрезки + санити-чек
minis-uicopy diff <orig> <render> [diffmap]
minis-uicopy residual <render>     # GLYPH-FORM vs RECONSTRUCTION
```

Рабочая папка: `--dir <папка>` или `UICOPY_DIR`, иначе текущая.

## Порядок работы

### 1. Подготовка
```sh
minis-uicopy --dir /var/minis/workspace/uicopy-<задача> init <скриншот>
```

### 2. Измерение
`measure hist` → палитра. `measure frame` → границы. `boxes` → список
элементов. `probe` → профили краёв, цвета текста, ink-высоты строк.

Ключевое: **фон занимает 70–85% площади**, поэтому глобальный MAE врёт в
разы. Всегда смотреть MAE по контенту и поэлементно.

### 3. Растровые ассеты
Аватары, логотипы, иконки — **кропать из оригинала** и ставить ровно в
координаты кропа. Даёт MAE 0.00. Не рисовать их CSS.

```sh
python3 -c "
from PIL import Image
im=Image.open('ORIGINAL.png')
im.crop((85,155,207,246)).save('assets/avatar.png')"
```

### 4. Границы — НЕ CSS-border
Главное открытие. В реальных UI граница это 4–8-пиксельный профиль:
```
разделитель таба = #384031 #2c3225 #3f4937 #56624e #76806e #7a8472 #5a6552
```
Однопиксельный `border` давал MAE 26; измеренный профиль — 0.16.

`stripes` / `bevel` / `edges` печатают готовый CSS: `linear-gradient` с
жёсткими 1px-стопами = точная копия пикселей.

### 5. Шрифт
Порядок важен именно такой:
1. `fontfit` — грубый отбор по ink-ширине (PIL).
2. `textfit` — прямое растровое MAE к кропу через **chromium**. PIL
   растеризует иначе, для финального выбора не годится.
3. `spacefit` — **построчный** letter-spacing. Один глобальный трекинг
   математически не подходит всем строкам: ширина растёт как (n−1)·spacing.

Признаки, которые ловят подмену:
- **толщина штриха** = доля пикселей с |d|>150 внутри ink-бокса. Рендер 86%
  против оригинала 65% ⇒ выбран bold там, где нужен normal.
- **cap-height / x-height / descender** по отдельным глифам: даёт кегль
  точнее, чем ширина строки.

### 6. Рендер и сравнение
```sh
minis-uicopy render index.html render_v1.png
minis-uicopy diff ORIGINAL.png render_v1.png diff_v1.png
```
`diff` выдаёт поэлементный MAE с сортировкой — сразу виден виновник. Дальше
попиксельно сравнить его профили/ink-bbox и править ТОЛЬКО под конкретное
измеренное расхождение.

### 7. Раздельный учёт остатка (обязательно перед словом «готово»)
```sh
minis-uicopy residual render_vN.png
```
Делит ошибку на два источника, которые нельзя смешивать:
- **GLYPH-FORM** — форма букв недоступного шрифта (внешнее ограничение);
- **RECONSTRUCTION** — геометрия, цвета, поверхности (это обязан уметь механизм).

Маска текста строится **из оригинала**, не из рендера — иначе можно объявить
текстом свои же ошибки. Расширение ±1px только внутри текстовых зон
(antialias-край глифа принадлежит шрифту, а не геометрии).

## Ловушки, каждая пойманная на практике

- **Профиль bevel нельзя снимать с последней строки элемента** — там он уже
  смешан с нижней кромкой (`#55604d` вместо `#5a6552` = угол, не боковина).
  Снимать в середине.
- **Профиль одной кнопки не подходит остальным** — отличаются и фаза, и
  оттенки. Только поэлементно.
- **Внешние кромки кадра могут быть не UI, а фоном за окном** (651 уникальный
  цвет в строке). Проверять число уникальных цветов перед заливкой одним.
- **Выравнивание может быть не центровым** там, где выглядит центровым: ink
  «OK» на x=650 при кнопке 638..775 (центр дал бы 692) ⇒ padding-left, а не
  `text-align:center`.
- **Загрязнённая цель измерения.** Окно вокруг текста может захватить bevel:
  «112×22» превратилось в истинные «92×14», когда в окно попала вертикальная
  полоса, присутствующая на ВСЕХ строках. Признак: ink-высота больше кегля.
- **Диагональные стыки** (переход разделителя в кромку) не выражаются ни
  border, ни одним градиентом: цвет меняется и по x, и по y. Решение — N
  однопиксельных строк, каждая со своим профилем.
- **Белая страница = ложные измерения.** `render` делает санити-чек (stddev),
  но при ручном вызове chromium путь обязан быть абсолютным.
- **Рендер обрезает низ.** chromium с точной высотой окна теряет ~7px снизу;
  `render` обходит это (рендер выше + кроп). Не вызывать chromium напрямую.

## Что НЕ делать

- Не вставлять растровые кропы текста вместо шрифта — цель редактируемый UI,
  а не вклейка картинки.
- Не искажать геометрию/цвета, чтобы замаскировать различие формы глифов.
- Не объявлять «готово» по глобальному MAE: он держится на однородном фоне.
- Не менять шрифт по косвенному признаку, если прямое растровое сравнение
  говорит иное.

## Критерий завершения

RECONSTRUCTION-часть остатка доведена до минимума, всё оставшееся объяснено и
отнесено к недоступным ассетам. Фиксируется: первый render, финальный render,
измеренный diff, список оставшихся расхождений, установленные причины и
отдельно — причины, которые невозможно установить без дополнительного входа.
